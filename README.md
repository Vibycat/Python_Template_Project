# Python Template Project

A clean, intentional, and scalable Python project structure designed
for:

-   Automation scripts\
-   Internal tooling\
-   Data pipelines\
-   CLI utilities\
-   API services\
-   General-purpose applications

This template enforces separation of concerns, predictable file
organization, and production-ready development habits.

------------------------------------------------------------------------

## Why This Template Exists

Most Python projects start simple and become chaotic over time.

This structure ensures:

-   Clear separation between logic, configuration, and utilities\
-   Centralized path management\
-   Dedicated data and logging directories\
-   Built-in testing structure\
-   Environment isolation support\
-   Scalable architecture for growth

It works for both small scripts and enterprise-grade internal tools.

## Project Structure

  MyProject/
│
├─ README.md
│  # Primary project documentation.
│  # Explains what the project does, how to install it,
│  # how to run it, and any important usage examples.
│
├─ pyproject.toml
│  # Modern Python project configuration file.
│  # Used by build tools (pip, poetry, hatch, etc.).
│  # Typically defines:
│  #   - project metadata
│  #   - dependencies
│  #   - build system configuration
│
├─ .gitignore
│  # Defines which files Git should ignore.
│  # Prevents committing things like:
│  #   - virtual environments
│  #   - compiled files (.pyc)
│  #   - logs
│  #   - local config files
│
├─ .env.example
│  # Template environment variables file.
│  # Developers copy this to `.env` locally and fill in values.
│  # Used for things like:
│  #   - API keys
│  #   - database URLs
│  #   - configuration secrets
│
├─ requirements-dev.txt
│  # Development-only dependencies.
│  # Usually includes tools such as:
│  #   - pytest
│  #   - black
│  #   - flake8
│  #   - mypy
│  #   - pre-commit
│
├─ src/
│  # Main source code directory.
│  # Using the "src layout" prevents accidental imports
│  # from the working directory during development.
│
│  └─ myproject/
│     # Root Python package for the application.
│
│     ├─ main.py
│     │  # Entry point for the application.
│     │  # This file typically contains:
│     │  #   - program startup logic
│     │  #   - CLI execution
│     │  #   - initialization of major components.
│
│     ├─ config.py
│     │  # Central configuration loader.
│     │  # Reads configuration from:
│     │  #   - environment variables
│     │  #   - .env files
│     │  #   - config defaults
│
│     ├─ paths.py
│     │  # Defines common filesystem paths used in the project.
│     │  # Example uses:
│     │  #   - data directories
│     │  #   - log locations
│     │  #   - configuration files
│
│     ├─ utils/
│     │  # Utility functions used across the project.
│
│     │  ├─ __init__.py
│     │  │  # Marks this directory as a Python package.
│     │  │  # May optionally expose utility functions
│     │  │  # for easier imports.
│
│     │  └─ helpers.py
│     │     # Collection of helper functions.
│     │     # Examples:
│     │     #   - formatting utilities
│     │     #   - reusable data operations
│     │     #   - validation helpers
│
│     └─ core/
│        # Core application logic.
│        # This is where the main functional behavior lives.
│
│        ├─ __init__.py
│        │  # Marks the directory as a package.
│        │
│        └─ logic.py
│           # Primary business logic implementation.
│           # Contains the functions/classes that perform
│           # the main work of the application.
│
├─ scripts/
│  # Utility scripts used for development or automation.
│
│  └─ run_local.ps1
│     # PowerShell script to launch the project locally.

│     #   - activate virtual environments

│  ├─ input/

## Design Philosophy

### 1. `/src` Layout

Keeps imports clean and avoids accidental working-directory issues.

### 2. Centralized Configuration

`config.py` and `paths.py` prevent hardcoded file paths scattered
throughout the codebase.

### 3. Separation of Responsibilities

-   `main.py` → Entry point\
-   `core/` → Business logic\
-   `utils/` → Reusable helpers\
-   `config.py` → Runtime configuration\
-   `data/` → Structured I/O\
-   `logs/` → Central logging\
-   `tests/` → Validation and regression safety

### 4. Environment Safety

`.env.example` included to safely manage API keys and secrets.

## Getting Started

### 1. Create Virtual Environment

``` bash
python -m venv .venv
source .venv/bin/activate
# Windows:
.venv\Scripts\activate
```

### 2. Install Dev Dependencies

``` bash
pip install -r requirements-dev.txt
```

### 3. Run the Project

``` bash
python -m myproject.main
```
